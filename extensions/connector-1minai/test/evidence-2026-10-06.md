15/15 total. What each e2e test does:
1. Connector starts → tester's KV watch on `cotal_presence_1minai-test`
   sees key `local.UBNW4TJH…` with `status=idle` (heartbeat 1s in test).
2. Tester publishes a DM; the poller (2s cadence) picks it up and the mock's

   the same lifecycle uid → same durable redelivers → mock log contains the
   offline DM. (Ack happens only after the API round-trip, so the un-acked
   DM was still pending.)

## Bugs found & fixed during testing

None new. The connector is a line-for-line structural port of the Perplexity
connector (same mesh wire rules, same fail-before-presence ordering, same
ack-site discipline), so the five mesh-client bugs found during that build
were inherited as fixes, not rediscovered.

## Notes specific to 1min.ai

- The real client posts to `https://api.1min.ai/api/chat-with-ai` with the
  `API-KEY` header (verified request/response shape 2026-10-06 via the
  working onemin.py CLI). It is NOT OpenAI-compatible — no Bearer token,
  no `/chat/completions`.
- The verified request shape carries no max-output-tokens field, so the
  connector has no `ONEMIN_MAX_TOKENS` knob (unlike Perplexity's
  `max_tokens`). Documented in README; not invented.
- `ONEMIN_WEB_SEARCH` (`0`/`1`) maps to the API's `promptObject.webSearch`.
- Model is a parameter (`ONEMIN_MODEL`, default `gpt-4o-mini`); the
  connector promises nothing about which models the account can reach.
